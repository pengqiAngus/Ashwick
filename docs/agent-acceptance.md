# Agent 聊天工作台 · 手动验收清单

前置：`pnpm db:up && pnpm db:migrate`，在 `.env` 中填好 `AI_PROVIDER_BASE_URL / AI_PROVIDER_API_KEY / AI_MODEL_ANALYST`，然后 `pnpm dev`。
数据库检查可用 `pnpm db:studio` 或直接连接 PostgreSQL。

| # | 验收重点 | 步骤 | 预期 |
|---|---|---|---|
| 1 | 直接打开 `/agent` 可手动开始分析 | 访问 `/agent`，页面停留 30 秒不操作；再输入“分析一下 BTC 接下来 24 小时的走势。”并回车 | 停留期间数据库 `AnalysisRun` 无新增；提交后跳转 `/agent/<id>`，步骤时间线逐步出现，最终有结构化报告卡与中文叙述 |
| 2 | 卡片入口自动发送且只发送一次 | Favorite 页点击任一卡片“AI 分析” | 跳转到新会话，首条用户消息以真实消息形式显示；`Message` 表该会话只有 1 条 user 消息，`AnalysisRun` 只有 1 条 |
| 3 | 已保存目标区间正确传入 | 在卡片中把区间改为新值但**不保存**，点击“AI 分析” | 首条消息中出现的是数据库中已保存的旧区间；未设置区间时消息不含区间句 |
| 4 | 刷新 / 重试 / Strict Mode / 双击不重复启动 | (a) 分析进行中刷新页面；(b) 快速双击“AI 分析”；(c) 开发模式（Strict Mode）下进入会话页；(d) 两个标签页打开同一会话 | 所有情况 `AnalysisRun` 对同一条消息只有 1 行（重试除外）；刷新后页面显示“正在同步进度”并继续展示步骤；第二个标签页不新建运行 |
| 5 | 步骤状态与真实执行对应 | 分析完成后对比页面步骤与 `AnalysisStep` 表 | 每步状态、耗时一致；未执行的步骤不显示“已完成”；工具卡片可展开查看输入输出 |
| 6 | 追问不重跑整条流程 | 完成后发送“为什么你认为目前是这个状态？” | 新运行只有 `route_intent → load_context → narrate` 三步，没有 `fetch_data`；回复开头注明数据截止时间 |
| 7 | 切换资产 / 周期后上下文正确 | 发送“再分析一下 ETH。”；再发送“换成未来 4 小时再分析一次。” | 分别创建新的完整运行；报告 symbol/horizon 更新；旧报告仍保留在历史消息中；右侧面板“当前上下文”更新 |
| 8 | 过期数据与预测不可用状态清晰 | 查看任一报告卡 | 顶部有“仅技术分析”徽标；“量化预测”区显示状态 unavailable、模型版本无、概率不可用；数据质量提示（如有）显示在报告顶部 |
| 9 | 指标、概率、价格位有计算依据 | 展开报告“支撑与阻力”“技术指标”“引用数据来源” | 每个价位带周期、触碰次数、距当前价百分比；情景中的价格全部来自支撑阻力列表；报告中没有模型自报的概率 |
| 10 | 停止能阻止后续步骤 | 分析进行中点击输入框右侧“停止” | 状态变“正在停止…”，随后运行标记“已停止”，未执行步骤为 `cancelled`；已完成内容保留；输入框恢复可用 |
| 11 | 原有功能不受影响 | 走一遍 README 原有验收步骤 2–9 | 搜索、K 线、收藏、区间高亮行为不变 |
| 12 | 手机端 | 375px 宽度打开会话页 | 单列布局，“当前上下文”折叠在顶部，输入框、停止、示例问题可点，无横向滚动 |
| 13 | 密钥不进浏览器；会话不串 | `pnpm build` 后执行 `grep -r "AI_PROVIDER_API_KEY" .next/static`；同时打开两个不同会话各发一条消息 | grep 无结果；两个会话的步骤、报告、交易对互不混淆 |

## 错误路径

- 未配置模型：`/agent` 顶部提示“尚未配置模型服务”；提交后会话页显示 503 错误信息，可在配置后点击“重试”。
- 无效交易对：发送“分析一下 FAKECOIN”，`resolve_symbol` 步骤失败并显示“不支持的交易对”，运行 failed，可重试。
- 币安限流 / 超时：`fetch_data` 步骤失败并显示具体错误，不生成伪报告。
- 数据不足：对上市不足 260 根日线的交易对分析，`quality_check` 失败并说明根数不足。
- 崩溃遗留：手动把某活跃运行的 `heartbeatAt` 改为 10 分钟前，再打开会话页 → 运行被标记 failed(orphaned)，出现“重试”。
